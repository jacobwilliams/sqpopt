       5              : !  **Dense** active-set QP solver for the linearized SQP subproblem
       6              : !  (the default for small problems, see `sqpopt_qp_auto`). Forms a dense
       7              : !  Jacobian and a dense Hessian from `sqpopt`'s usual sparse/matrix-free
       8              : !  representations each time it is called, then solves the QP with
       9              : !  classical primal active-set machinery (Nocedal & Wright, *Numerical
      10              : !  Optimization*, Ch. 16.5): a null-space/reduced-Hessian step within the
      11              : !  current working set (Householder QR + Cholesky, see
      12              : !  [[sqpopt_dense_linalg_module]]), a ratio test to add a newly-binding
      13              : !  bound/constraint to the working set, and a Lagrange-multiplier sign
      14              : !  check to drop one when the current working set's minimizer has been
      15              : !  reached. Since it forms `O(n^2)`/`O(mn)` dense arrays every call, it is
      16              : !  only suitable for small-to-moderate `n`/`m`.
      17              : !
      18              : !  General constraints and variable bounds are treated uniformly as
      19              : !  "rows" of a single constraint matrix, each two-sided
      20              : !  (`row_lb<=row^T u<=row_ub`); equality rows (`row_lb==row_ub`) never
      21              : !  leave the working set once in it.
      22              : !
      23              : !  **Elastic mode.** A primal active-set method needs a feasible starting
      24              : !  point. Rather than a separate phase-1 problem, every general constraint
      25              : !  that is violated at `p=0` is made *elastic*: it gets a nonnegative slack
      26              : !  `s_i` (entering the row with the sign that can restore feasibility)
      27              : !  with an \( \ell_1 \) penalty \( \rho s_i \) in the objective (SNOPT's
      28              : !  elastic mode, Fletcher's S\( \ell_1 \)QP). `p=0` plus those slacks is
      29              : !  then feasible, and all other rows are kept hard. For a large enough
      30              : !  weight \( \rho \) (more than the largest multiplier), the slacks are zero
      31              : !  at the solution whenever the linearized constraints are consistent,
      32              : !  and the solution is that of the original QP. If slacks are still
      33              : !  positive at the solution, \( \rho \) is increased (warm-starting from
      34              : !  the current working set) up to `elastic_weight_max`; if they are still
      35              : !  positive then, the linearized constraints are inconsistent, and
      36              : !  `istat=sqpopt_infeasible` is returned, with `p` the elastic solution
      37              : !  (which minimizes the \( \ell_1 \) violation of the linearized
      38              : !  constraints, then the QP objective).
      39              : !
      40              : !  **Forced elastic mode** (`force_sign`, `force_weight`, set for one solve
      41              : !  by [[sqpopt_qp_solver_module]] when the SQP iteration re-solves a QP
      42              : !  with diverging-multiplier constraints elastic, see
      43              : !  `options%elastic_multiplier_limit`): the chosen rows get an elastic
      44              : !  slack in the given direction even if they aren't violated at the
      45              : !  starting step, every slack has the fixed weight `force_weight` (not
      46              : !  raised), and positive slacks at the solution are accepted
      47              : !  (`istat=sqpopt_success`): the solution is that of the \( \ell_1 \)
      48              : !  penalty QP, whose multipliers on those rows are at most the weight.
      49              : !
      50              : !  **Crash and warm start.** Rather than from `p=0`, the iterations start
      51              : !  from the minimum-norm step that satisfies an initial guess of the
      52              : !  working set: the previous solve's final working set (a *warm start*,
      53              : !  when `warm_start` is on and the problem size is unchanged -- near an SQP
      54              : !  solution the active set settles, and the QP then finishes in one or two
      55              : !  iterations), or else the equality constraints and fixed variables (a
      56              : !  *crash* start, so equality constraints don't each need an elastic slack
      57              : !  and an iteration to remove it). Any variable bounds this step violates
      58              : !  are added to the guess and the step recomputed (a few rounds), then it
      59              : !  is clipped to the bounds; only the rows it still violates get elastic
      60              : !  slacks. The guess only sets the starting point: optimality is still
      61              : !  established by the active-set iterations.
      62              : !
      63              : !  **Robustness.** Rows are only ever added to the working set if they are
      64              : !  linearly independent of it (the initial working set is built with a
      65              : !  Gram-Schmidt independence check; a row blocking a step along a
      66              : !  null-space direction is independent by construction), so the null-space
      67              : !  basis is always well defined. If the reduced Hessian \( Z^THZ \) is not
      68              : !  positive definite (e.g. an indefinite SR1 approximation, or zero
      69              : !  curvature along an elastic slack), a direction of nonpositive curvature
      70              : !  is followed to the nearest blocking row instead of taking a (huge or
      71              : !  undefined) Newton step. Tolerances are relative to the problem scale.
