       5              : !  The line searches used to globalize the SQP iterations (ensures
       6              : !  progress towards both optimality and feasibility). The acceptance tests
       7              : !  they use are in their own modules, held here as components: the merit
       8              : !  function and its penalty parameter (`merit`, see
       9              : !  [[sqpopt_merit_module]]), the filter (`filter`, see
      10              : !  [[sqpopt_filter_module]]), and the funnel (`funnel`, see
      11              : !  [[sqpopt_funnel_module]]). The trust region (see
      12              : !  [[sqpopt_trust_region_module]]) uses the same components, so the two
      13              : !  globalizations share the filter or funnel.
      14              : !
      15              : !  Five line search strategies are available (`sqpopt_linesearch_type%mode`):
      16              : !
      17              : !  * `sqpopt_linesearch_armijo` -- a standard backtracking line search
      18              : !    with an Armijo-type sufficient-decrease test on the merit function (as
      19              : !    used by default in `slsqp`).
      20              : !  * `sqpopt_linesearch_exact` -- (approximately) minimizes the merit
      21              : !    function along the search direction using the derivative-free `fmin`
      22              : !    routine (from the `fmin` dependency), rather than a hand-written
      23              : !    exact-search implementation.
      24              : !  * `sqpopt_linesearch_watchdog` -- Powell's watchdog technique
      25              : !    (Chamberlain, Lemarechal, Pedersen & Powell, *Math. Prog. Study 16*
      26              : !    (1982)): tracks the best point found so
      27              : !    far and, for a short window after a genuine improvement, *relaxes* the
      28              : !    sufficient-decrease test to allow the merit function to temporarily
      29              : !    get worse (accepting the full quasi-Newton step outright) rather than
      30              : !    stalling near a curved/simultaneously-active constraint boundary (the
      31              : !    Maratos effect). If the relaxed window is used up without a new best
      32              : !    point, it backtracks all the way to the best point found so far and
      33              : !    disables relaxed acceptance for `watchdog_cooldown_len` iterations.
      34              : !    This targets the same failure mode as the second-order correction and
      35              : !    the augmented Lagrangian merit function, via a different mechanism.
      36              : !  * `sqpopt_linesearch_filter` (**default**) -- a **filter** line search (Fletcher &
      37              : !    Leyffer, *"Nonlinear programming without a penalty function"*, Math.
      38              : !    Program. 91 (2002)), with the globally convergent line-search rules of
      39              : !    Wächter & Biegler (*"Line search filter methods for nonlinear
      40              : !    programming: motivation and global convergence"*, SIAM J. Optim. 16
      41              : !    (2005), and the IPOPT paper, Math. Program. 106 (2006)): no merit
      42              : !    function or penalty parameter; a trial point is judged by the pair
      43              : !    \( (\theta, \varphi) \) of \( \ell_1 \) constraint violation and
      44              : !    objective value, and must not be dominated by the filter (see
      45              : !    [[sqpopt_filter_module]]). See [[filter_line_search]].
      46              : !    It is the default: on the Hock-Schittkowski test set (see
      47              : !    `test/test_hs_suite.f90`) it solves the most problems, with the
      48              : !    fewest function evaluations, of all the line search / merit function /
      49              : !    penalty combinations (and it has no penalty parameter to tune).
      50              : !  * `sqpopt_linesearch_funnel` -- the **funnel** method (Kiessling, Leyffer
      51              : !    & Vanaret, *"A unified funnel restoration SQP algorithm"*, Math.
      52              : !    Program. (2025); as implemented in the Uno solver): like the filter, no
      53              : !    merit function or penalty parameter, but the filter's list of points is
      54              : !    replaced by a single number, the funnel width, a bound on the
      55              : !    \( \ell_1 \) constraint violation that shrinks as the iterations
      56              : !    progress. A trial point must be inside the funnel; the same switching
      57              : !    condition then decides whether it must reduce the objective (an
      58              : !    Armijo test, "f-type") or sufficiently reduce the violation relative
      59              : !    to the funnel ("h-type", which shrinks the funnel). See
      60              : !    [[funnel_line_search]].
      61              : !
      62              : !  Two options from NLPQLP (Schittkowski) apply to the backtracking
      63              : !  searches: `interpolate` (on by default) chooses each backtracking step
      64              : !  length by safeguarded quadratic interpolation (see
      65              : !  [[next_step_length]]) rather than a fixed factor; and `nonmonotone_len`
      66              : !  (off by default) retries a failed search non-monotonically, against the
      67              : !  worst of the recent iterates (not used by the funnel search). On the Hock-Schittkowski test set the
      68              : !  interpolation solves one more problem with the filter search, with
      69              : !  fewer function evaluations (and a third fewer with the \( \ell_1 \)
      70              : !  merit function); the non-monotone retry doesn't help the filter search,
      71              : !  but does help the merit-function ones (e.g. with the augmented
      72              : !  Lagrangian and interpolation, 273 solved instead of 270).
      73              : !
      74              : !  All three of the merit-function-based modes start each search from an
      75              : !  initial trial step length
      76              : !  \( \alpha_0 \le 1 \) (see [[initial_step_length]]) rather than always
      77              : !  `1`, capped by `major_step_limit` (SNOPT's "Major step limit" option)
      78              : !  so that no variable can change by more than a factor of
      79              : !  `major_step_limit` relative to its current magnitude in a single major
      80              : !  iteration -- a QP step that is technically feasible can still be
      81              : !  unreasonably large (e.g. from a poorly-scaled problem or an early,
      82              : !  inaccurate Hessian approximation), and this guards against the
      83              : !  resulting merit-function evaluations diverging or becoming undefined.
      84              : !
      85              : !  At `options%print_level >= 3`, every trial point (step length, merit
      86              : !  value or violation and objective, and whether and why it was accepted)
      87              : !  is written to the detailed log (`log`, see [[sqpopt_log_module]]), and
      88              : !  `used_soc`, `used_nonmonotone`, and `used_relaxed` report what the last
      89              : !  search used, for the iteration log's flags.
