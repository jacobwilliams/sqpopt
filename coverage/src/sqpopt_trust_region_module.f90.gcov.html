       5              : !  Opt-in **trust-region** globalization strategy for the SQP major
       6              : !  iteration -- an alternative to the line-search-based approach in
       7              : !  [[sqpopt_linesearch_module]] (see `plan/TRUST_REGION_PLAN.md` for the
       8              : !  full design rationale). Disabled by default (`sqpopt_trust_region_type
       9              : !  %enabled = .false.`), in which case `sqpopt_iterate_module` behaves
      10              : !  exactly as if this module did not exist.
      11              : !
      12              : !  When enabled, a major iteration no longer solves the linearized QP
      13              : !  once and then searches for a step length `alpha` along the resulting
      14              : !  `p`. Instead, the QP is re-solved as needed with a **trust-region
      15              : !  radius**: the variable bounds passed to `qp_solver%solve` are
      16              : !  temporarily tightened to `max(x_lb,x-radius)`/`min(x_ub,x+radius)`
      17              : !  (an \( \ell_\infty \) ball around `x`, intersected with the problem's
      18              : !  own bounds -- exactly the box constraint Fletcher & Leyffer's own
      19              : !  trust-region QP uses, and for the same reason: it keeps the QP a
      20              : !  simple bound-constrained problem, not a genuinely quadratically-
      21              : !  constrained one). No changes are needed to any of the three
      22              : !  `qp_solver_mode`s to support this, since they all already enforce
      23              : !  variable bounds.
      24              : !
      25              : !  The resulting step `p` is tested for acceptance (and, if it is rejected
      26              : !  without reducing the constraint violation, so is its second-order
      27              : !  correction, see [[sqpopt_soc_module]]), and the radius is grown or
      28              : !  shrunk accordingly:
      29              : !
      30              : !  * if `linesearch%mode == sqpopt_linesearch_filter`, acceptance uses the
      31              : !    same filter test as the filter line search (`linesearch%filter%accept`,
      32              : !    with the quadratic model's predicted decrease `q` in place of
      33              : !    \( g^Tp \) in the switching condition) -- a trust-region filter-SQP
      34              : !    method in the spirit of Fletcher & Leyffer (`references/fletcher.pdf`).
      35              : !  * if `linesearch%mode == sqpopt_linesearch_funnel`, acceptance uses the
      36              : !    funnel test of the funnel line search (`linesearch%funnel%accept`,
      37              : !    with `q` as the predicted decrease) -- the trust-region funnel SQP
      38              : !    method of Kiessling, Leyffer & Vanaret (Uno's `funnelsqp` preset).
      39              : !  * otherwise, acceptance uses the classical trust-region-SQP ratio test
      40              : !    (Nocedal & Wright, *Numerical Optimization*, Ch. 18): \( \rho =
      41              : !    \text{ared}/\text{pred} \), the ratio of the actual to the
      42              : !    predicted decrease in the merit function selected by
      43              : !    `linesearch%merit%mode`, accepted when \( \rho \ge \eta_1 \).
      44              : !
      45              : !  If a step is rejected, the radius is shrunk (`shrink_factor`) and the
      46              : !  QP is re-solved (bounded by `max_retries` retries per major iteration)
      47              : !  -- there is no `alpha` to backtrack along, since a genuinely different
      48              : !  `p` is computed each time. Trial points where `f` or `c` is not finite
      49              : !  are always rejected. If every retry is rejected, no step is taken
      50              : !  (`istat=sqpopt_line_search_failed`), as for a failed line search.
      51              : !
      52              : !  Because this bypasses `linesearch%search` entirely, the line-search-
      53              : !  specific options (`major_step_limit`, `alpha_min`/`sigma`/`backtrack`/
      54              : !  `max_ls_iter`, and the watchdog fields) are not used when trust region
      55              : !  is enabled -- there is no `alpha`, so nothing to cap or backtrack.
      56              : !
      57              : !  At `options%print_level >= 3`, every QP re-solve (radius, QP status, and
      58              : !  the trial point's ratio, or violation and objective, and whether it was
      59              : !  accepted) is written to the detailed log (`log`, see
      60              : !  [[sqpopt_log_module]]).
