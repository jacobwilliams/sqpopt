       6              : !  (`options%linear_solver = sqpopt_linear_solver_mumps`):
       7              : !  [MUMPS](https://mumps-solver.org), a multifrontal \( LDL^T \)
       8              : !  factorization with pivoting and OpenMP threads. Its inertia is always
       9              : !  known (`icntl(13) = 1` makes the count of negative pivots exact), and a
      10              : !  singular matrix's null pivots are detected (`icntl(24) = 1`).
      11              : !
      12              : !  This is the library's only interface to MUMPS, and the only source file
      13              : !  that depends on the `HAS_MUMPS` preprocessor directive: without it,
      14              : !  `sqpopt_has_mumps` is false and [[mumps_start]] always fails. With it,
      15              : !  the library must be linked with the sequential, double precision MUMPS
      16              : !  library, and compiled in double precision (the default kind, see
      17              : !  [[sqpopt_kinds]]).
      18              : !
      19              : !  **Threads.** MUMPS and the BLAS under it can use OpenMP threads, if they
      20              : !  were built with OpenMP (conda-forge's `mumps-seq` is): the `threads`
      21              : !  argument of [[mumps_start]], `1` by default, or `0` to leave it to the
      22              : !  OpenMP environment (`OMP_NUM_THREADS`, or every core). On small matrices
      23              : !  the threads cost far more time than they save (the 305
      24              : !  Hock-Schittkowski problems took 24.5 s with 10 threads, and 1.4 s with
      25              : !  one). Whether more threads help a large matrix depends on its factors:
      26              : !  the threads work inside the dense blocks of the factorization (its
      27              : !  frontal matrices), so they need those to be large. Measured (analysis,
      28              : !  two factorizations, and a solve; 1, 2, 4, and 8 threads): a 3-D grid
      29              : !  matrix of order 216,000 took 11.5, 7.0, 4.9, and 4.8 s; a 2-D grid
      30              : !  matrix of order 490,000 took 2.0 s with any number; and the banded KKT
      31              : !  matrices of `example/benchmark_large.f90` gained nothing either. MUMPS
      32              : !  sets the number of threads when it is called and restores it when it
      33              : !  returns, so the rest of the program is not affected.
