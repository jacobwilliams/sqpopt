       5              : !  Defines the nonlinear program (NLP) that is to be solved:
       6              : !
       7              : !  $$ \min_{x} f(x) $$
       8              : !
       9              : !  subject to:
      10              : !
      11              : !  $$ c_l \le c(x) \le c_u $$
      12              : !  $$ x_l \le x \le x_u $$
      13              : !
      14              : !  where \( c(x) \) is a vector of nonlinear constraints. An equality
      15              : !  constraint is specified by setting the corresponding elements of
      16              : !  \( c_l \) and \( c_u \) to the same value, and an inequality
      17              : !  constraint by setting them to different values (using \( \pm\infty \)
      18              : !  for one-sided inequalities). Variable bounds are specified similarly
      19              : !  via \( x_l \) and \( x_u \).
      20              : !
      21              : !  The Jacobian of \( c(x) \) and the Hessian of the Lagrangian are
      22              : !  never treated as dense \( m \times n \) or \( n \times n \) arrays:
      23              : !  their (fixed) sparsity patterns are supplied once as 1-based COO
      24              : !  `irow`/`icol` triplets (the same convention used by the `lusol` and
      25              : !  `LSQR` dependencies), and the user-supplied evaluation
      26              : !  routines only need to fill in the corresponding nonzero *values* on
      27              : !  each call.
      28              : !
      29              : !  **User functions.** The problem is defined by two routines (see
      30              : !  [[set_functions]]): `fc`, which evaluates the objective \( f(x) \) and
      31              : !  the constraints \( c(x) \) together, and `gjac`, which evaluates the
      32              : !  objective gradient \( \nabla f(x) \) and the nonzero values of the
      33              : !  constraint Jacobian together (and, optionally, `hess` for an exact
      34              : !  Hessian of the Lagrangian). Every user function has two trailing
      35              : !  arguments:
      36              : !
      37              : !  * `status` (`integer, intent(inout)`): `0` on entry. Leave it `0` on
      38              : !    success; set it `> 0` if the function cannot be evaluated at `x` (e.g.
      39              : !    a domain error) -- the solver then treats the point like one where
      40              : !    the function returned NaN, and backs off from it -- or `< 0` to ask the
      41              : !    solver to stop (`istat=sqpopt_user_requested_stop`).
      42              : !  * `data` (`class(*), intent(inout), optional`): the user data object
      43              : !    given to [[set_functions]] (absent if none was given), for passing any
      44              : !    context to the functions without module variables; use `select type`
      45              : !    to access it.
      46              : !
      47              : !  **Evaluation layer.** The solver evaluates everything through the
      48              : !  type-bound [[eval_f_cached|f]], [[eval_c_cached|c]], [[eval_g_cached|g]],
      49              : !  and [[eval_jac_cached|jac]] methods, which handle `status`/`data`, count
      50              : !  the user calls, keep a small cache of recent evaluations (so e.g. the
      51              : !  point accepted by a line search is not evaluated again, and asking for
      52              : !  `c` at a point where `f` was just evaluated doesn't call `fc` again),
      53              : !  and apply the objective and constraint scaling (see
      54              : !  [[compute_scaling]]): the solver works with \( s_f f \) and
      55              : !  \( s_{c,i} c_i \).
