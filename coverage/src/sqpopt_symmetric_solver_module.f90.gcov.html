       5              : !  A direct solver for symmetric indefinite linear systems
       6              : !  \( A x = b \), with one of four backends
       7              : !  (`options%linear_solver`), each in a module of its own, behind the
       8              : !  interface of [[sqpopt_sparse_ldl_module]]:
       9              : !
      10              : !  * `sqpopt_linear_solver_qdldl` (the default, in every build): QDLDL
      11              : !    ([[sqpopt_qdldl_ldl_module]]), without pivoting, single-threaded, with
      12              : !    very little overhead, always available;
      13              : !  * `sqpopt_linear_solver_mumps`: MUMPS ([[sqpopt_mumps_ldl_module]]), with
      14              : !    pivoting and threads, in a library built with it (`sqpopt_has_mumps`);
      15              : !  * `sqpopt_linear_solver_dense` (opt-in): the matrix as a dense array
      16              : !    ([[sqpopt_dense_ldl_module]]), with pivoting and the exact inertia, for
      17              : !    small matrices only (\( O(n^3) \) per factorization; it refuses an
      18              : !    order above `dense_max_order`, see [[sqpopt_linear_solver_max_order]]);
      19              : !  * `sqpopt_linear_solver_lapack` (opt-in): the same dense matrix, factored
      20              : !    by LAPACK's `DSYTRF` ([[sqpopt_lapack_ldl_type]]), in a library built
      21              : !    with LAPACK (`sqpopt_has_lapack`).
      22              : !
      23              : !  This module chooses the backend, and does what is the same for both:
      24              : !  the iterative refinement of the solves, the counts, and the timing.
      25              : !
      26              : !  **Which one.** Measured (release; see the user guide's "Linear solver"
      27              : !  section): on the banded and chained problems of
      28              : !  `example/benchmark_large.f90` (5,000 to 1,000,000 variables) both take
      29              : !  the same iterations, and QDLDL's factorizations take 7 to 30 times less
      30              : !  time; on the Hock-Schittkowski problems the quasi-Newton Hessians give
      31              : !  the same results with both (QDLDL's faster), but the exact Hessian with
      32              : !  inertia control needs about 45% more evaluations with QDLDL, which can't
      33              : !  tell the inertia of a Hessian with zeros on its diagonal (see
      34              : !  `inertia_known`). On grids (`example/sparse_solvers.f90`), MUMPS
      35              : !  refactors 2 to 10 times faster in 2-D and 9 to 34 times in 3-D, where
      36              : !  the factors have large dense blocks (and its threads help), though its
      37              : !  first factorization, with its analysis, can cost much more (72 s against
      38              : !  4.5 s for a 2-D KKT matrix of order 735,000). So MUMPS is the better
      39              : !  choice for the exact Hessian with inertia control, and for problems
      40              : !  coupled in two or three dimensions that refactor many times. For a small
      41              : !  problem with the exact Hessian and inertia control, the dense backend
      42              : !  gives MUMPS's results (on the Hock-Schittkowski problems, 9,426
      43              : !  evaluations against MUMPS's 9,400 and QDLDL's 13,654) at QDLDL's speed.
      44              : !
      45              : !  How it is used:
      46              : !
      47              : !  1. [[symmetric_solver_initialize]] with the sparsity pattern (the entries
      48              : !     of one triangle, in coordinate form; entries given more than once are
      49              : !     added together). QDLDL analyses (orders) it here, MUMPS in the first
      50              : !     factorization; either way only once, so a matrix whose values change
      51              : !     but whose pattern doesn't is cheap to refactor.
      52              : !  2. [[symmetric_solver_factor]] with the values of those entries. The
      53              : !     factorization gives the *inertia* of the matrix: `n_negative`
      54              : !     negative and `n_null` zero eigenvalues, if `inertia_known` (else those
      55              : !     are the counts of the factors, which are not the matrix's).
      56              : !  3. [[symmetric_solver_solve]], any number of times, for right-hand sides.
      57              : !     Each solution is improved by iterative refinement.
      58              : !  4. [[symmetric_solver_destroy]] to free it. A backend may hold pointers
      59              : !     (MUMPS), so it must not be copied.
      60              : !
      61              : !  A singular matrix is not an error: its null pivots are counted
      62              : !  (`n_null`), and a solve then returns one of the solutions of a consistent
      63              : !  system.
