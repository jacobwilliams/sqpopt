Various documents used for planning and creating this library.
* [ROADMAP.md](ROADMAP.md) -- current plan (v2): review findings, bugs, and prioritized roadmap.
* [INERTIA_CONTROL.md](INERTIA_CONTROL.md) -- inertia control for indefinite Hessians, and the case for (and against) an optional sparse LDLᵀ solver such as MUMPS (open decision §8.3 of the roadmap). Its §9 describes what was implemented.
* [QDLDL_PLAN.md](QDLDL_PLAN.md) -- plan for a standalone fpm package: a Fortran port of QDLDL (OSQP's sparse LDLᵀ for quasi-definite matrices), with orderings, inertia, and regularization; its §9 is what sqpopt would need from it, as a sparse solver available without MUMPS.
* [DAQP_PLAN.md](DAQP_PLAN.md) -- plan for a standalone fpm package: a Fortran port of DAQP (a dual active-set solver for dense convex QPs, with recursive LDLᵀ updates), with the C code as a git submodule to compare the port's accuracy and speed against; its §10 is what sqpopt would need from it, as a faster dense QP solver (roadmap F30).
* [SSIDS_PLAN.md](SSIDS_PLAN.md) -- plan for a standalone fpm package: SSIDS (SPRAL's sparse symmetric indefinite solver, with pivoting and inertia) extracted from SPRAL, its C++ CPU kernels translated to Fortran, its GPU code dropped, and METIS/BLAS/LAPACK made optional; its §10 is what sqpopt would need from it, as a fourth sparse backend (roadmap F25).
* [MUMPS_PLAN.md](MUMPS_PLAN.md) -- further uses of MUMPS for large problems (direct QP steps, least-squares solves, quasi-Newton Hessians): the plan, and in its §8 what was implemented and measured.
* [YUKON_COMPARISON.md](YUKON_COMPARISON.md) -- comparison with Yukon, the SQP optimizer of NASA's GMAT, and the ideas worth exploring from it (a reverse-communication interface, a maximum step for each variable, built-in finite differences).
* [FILTERSD_COMPARISON.md](FILTERSD_COMPARISON.md) -- comparison with filterSD, Roger Fletcher's filter and trust-region code without second derivatives, and the ideas worth exploring from it (a derivative checker, a report of the infeasible constraints).
* [OPENSQP_COMPARISON.md](OPENSQP_COMPARISON.md) -- comparison with OpenSQP, a dense SQP method in Python (Joshy and Hwang, 2025), and the ideas worth exploring from its paper (a CUTEst benchmark through PyCUTEst and the Python bindings, with performance profiles).
* [OPTGRA_COMPARISON.md](OPTGRA_COMPARISON.md) -- comparison with OPTGRA, ESA's gradient-projection optimizer for trajectory design, and the ideas worth exploring from it (scale factors for the variables, sensitivities of the solution, names in the output).
