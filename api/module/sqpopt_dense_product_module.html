dense_matvec dense_matmul

Dense matrix-vector and matrix-matrix products, in the caller's arrays: the library's replacement for the matmul intrinsic, which it doesn't use. An expression with matmul (nested, or with a transpose, or as an actual argument) needs an array temporary for its result, and some compilers put those on the stack (the Intel compilers by default, gfortran with -fstack-arrays or -Ofast), which a moderately large matrix then overflows (Windows's default stack is 1 MB, the size of a 350 by 350 matrix). These routines form nothing: the result goes into an array the caller has allocated, and op(A) is never formed.

The products are explicit loops (column-oriented, the order of the arrays' storage), in any real kind; in a library built with LAPACK (the HAS_LAPACK preprocessor directive, in double precision, which links BLAS too), BLAS's DGEMV and DGEMM instead, whenever the arrays are contiguous (a section that isn't, e.g. the leading rows of a matrix, uses the loops, since BLAS would need it copied). The two builds' products then differ in rounding, and so can their iterates.
